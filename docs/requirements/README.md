## 記述の約束

- ID は `FR-xx` / `NFR-xx` / `CON-xx`。**既存 ID は再利用しない。** 廃止する場合は項目を残して「廃止」と明記し、欠番にする
- 1項目1要件。複数の要求を混ぜない
- **実現手段を書かない。** 「`mutedInfo.reason` で」「バッジの背景色で」は仕様（`docs/specs/`）か ADR の領分
- 曖昧語（適切に、必要に応じて）を残さない。**満たしているかを誰が見ても判定できる形**まで落とす
- 各項目に **優先度** と **状態** と **仕様**（対応する `SPEC-xx`）を書く

| 優先度 | 意味 |
| --- | --- |
| 必須 | 満たさないと公開できない |
| 重要 | 満たさないと利用者が困るが、公開は止めない |
| 希望 | あれば良い。着手は未定 |

| 状態 | 意味 |
| --- | --- |
| ✅ | 満たしている。根拠（自動テスト・確認手順）が仕様に書いてある |
| ⚠️ | 一部だけ満たしている、または根拠が足りない |
| ❌ | 満たしていない（未実装を含む） |
| 🚧 | ドラフト。利用者の確認を受けていない |
