# ADR-0002 更新のときも、利用者のアンミュートを残さずに全タブをミュートする

| | |
| --- | --- |
| 状態 | 採択（2026-10-11）。**1.1.1 で実装** |
| 対象 | FR-05, FR-07, CON-04 |
| 仕様 | [SPEC-SW-03](../specs/service-worker.md) |
| 発端 | 1.1.1 の開発中に「更新のときは利用者のアンミュートを残す」修正を試み、Playwright で確かめたところ、更新のたびに全タブがアンミュートのまま残った |

---

## 決定

**`onInstalled` では理由（インストール・更新）を問わず、`muteTab(tab, true)` で全タブを強制的にミュートする。**
更新の前に利用者がアンミュートしていたタブも、ミュートに戻る。

Chrome は拡張機能をアンロードするとき、その拡張機能がミュートしたタブをすべてアンミュートし、
`mutedInfo` を `{ muted: false, reason: 'extension', extensionId: <自分> }` にする（CON-04）。
これは利用者がアイコンでアンミュートしたタブとまったく同じ値で、更新の後には区別できない。

| 案 | 判定 |
| --- | --- |
| **(a) 採用** 更新でも強制する | 全タブが確実にミュートに戻る。失うのは「更新の前にアンミュートしていた」という選択だけで、利用者はアイコンを押し直せば戻せる |
| (b) 更新では `reason` を尊重する（強制しない） | 却下。上記のとおり、Chrome がアンミュートした全タブを「利用者がアンミュートした」と読んでしまい、**全タブがアンミュートのまま残る**。Playwright で実際に確かめた |
| (c) 更新の前にアンミュートしていたタブを記録しておき、更新後に区別する | 却下。記録には `storage` 権限が要る（NFR-01 / CON-03）。メモリは更新で消える |

## 代償

利用者から見ると「拡張機能が更新されると、アンミュートしていたタブがミュートに戻る」。
戻るのは音が止まる側なので、予期しない音が鳴るよりも目的（[background.md](../requirements/background.md)）に沿う。
