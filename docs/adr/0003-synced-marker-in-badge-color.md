# ADR-0003 再有効化を、バッジの背景色に付けた目印で検出する

| | |
| --- | --- |
| 状態 | 採択（2026-10-11）。**1.1.1 で実装**（コミット 4005141） |
| 対象 | FR-07, NFR-01, NFR-03, CON-04 |
| 仕様 | [SPEC-SW-04](../specs/service-worker.md) |
| 発端 | 2026-10-11 のコードレビュー（`/code-review`）で指摘され、Playwright で再現した。無効化→再有効化すると全タブがアンミュートのまま残り、ページを遷移してもミュートに戻らなかった（1.1.0 では遷移したタブだけはミュートに戻っていたので、1.1.1 の開発版はこの点で悪化していた） |

---

## 問題

無効化でも Chrome は全タブをアンミュートする（CON-04）。ところが再有効化では、`onInstalled` も `onStartup` も来ない。
来るのは Service Worker の起動だけで、これは**アイドル停止からの再開でも同じように起きる**。
再開のたびに全タブを強制ミュートすると、利用者のアンミュートが 30 秒ほどで消えてしまう（NFR-03 に反する）。

**「拡張機能が読み込まれてから、まだ全タブを同期していない」ことを、権限を使わずに知る手段**が要る。

## 決定

**グローバルなバッジ背景色を「同期済み」の目印にする。** `syncAllTabs()` が付け、Service Worker の起動ごとに読み、無ければ同期する。

| 性質 | 確認 |
| --- | --- |
| Service Worker のアイドル停止→再開では残る | Playwright で確認（DevTools を切断して 45 秒待つ） |
| 拡張機能のアンロード（更新・無効化）では消える | Playwright で確認 |
| 権限が要らない | `action` の宣言だけで使える |
| 表示に影響しない | バッジの文字を設定しないので、背景色は表に出ない |

| 案 | 判定 |
| --- | --- |
| **(a) 採用** グローバルなバッジ背景色 | 上表 |
| (b) `chrome.storage.session` に目印を置く | 却下。`storage` 権限が要る（NFR-01） |
| (c) Service Worker のグローバル変数に置く | 却下。アイドル停止で消えるので、再開と再有効化を区別できない |
| (d) 起動のたびに必ず全タブを強制ミュートする | 却下。アイドル停止から再開するたびに利用者のアンミュートが消える |
| (e) グローバルなツールチップ（`setTitle`）を目印にする | 却下。アイコンにマウスを載せたときの文字が変わり、表に出る |
| (f) `chrome.management` の通知で検出する | 却下。`management` 権限が要る（NFR-01） |

## 判定に失敗したとき

**目印を読めなかったら、同期しない側に倒す。** 同期する側に倒すと、何かの理由で読めない状態が続いたとき、
Service Worker が起きるたびに利用者のアンミュートが消える。同期しない側の失敗は「再有効化の後にアンミュートのタブが残る」で、
遷移しても戻らないが、アイコンで直せる。

## 代償

- バッジの背景色を、本来の用途（バッジの表示）に使えなくなる。バッジを使う機能を足すときは、目印を別の手段に移すこと
- 目印の性質（アイドル停止で残り、アンロードで消える）は Chrome の文書で約束されたものではなく、実測に頼っている。
  Chrome の版が上がって変わったら、`tests/lifecycle.spec.mjs` の2件（`無効化→再有効化…` と `アイドル停止…`）が落ちて気づける
