## FR-05 利用者がアンミュートしたタブは、閉じるまでミュートし直さない

利用者がアンミュートしたタブは、ページを遷移してもアンミュートのままであること。

判定基準:

1. アイコンでアンミュートしたタブは、遷移してもアンミュートのまま
2. タブのスピーカーでアンミュートしたタブも、遷移してもアンミュートのまま
3. アンミュートしたタブを閉じ、同じページを新しいタブで開き直すと、ミュートされている（タブを閉じたら選択は消える）
4. 拡張機能が裏で停止・再開しても（NFR-03）、1・2 は変わらない

| | |
| --- | --- |
| 優先度 | 必須 |
| 状態 | ✅（1.1.0 から） |
| 仕様 | SPEC-SW-02, SPEC-SW-04, SPEC-SW-06 |
| 例外 | FR-07 の契機（起動・更新・再有効化）では、アンミュートしていたタブもミュートに戻る |

---

## FR-06 ツールバーのアイコンがタブのミュート状態を表す

見ているタブがミュートならミュートのアイコン、アンミュートならアンミュートのアイコンが出ていること。
ページを遷移した後も一致していること。

| | |
| --- | --- |
| 優先度 | 重要 |
| 状態 | ✅（遷移後に一致しなくなる不具合を 1.1.1 で是正。SPEC-SW-05） |
| 仕様 | SPEC-SW-05, SPEC-SW-07, SPEC-MF-04 |

---

## FR-07 起動・インストール・更新・再有効化のときに、すべてのタブをミュートする

次の契機の直後に、開いているすべてのタブがミュートされていること。
**利用者がアンミュートしていたタブも含む**（FR-05 の選択はここで消える）。

| 契機 | アンミュートを消す理由 |
| --- | --- |
| インストール | 入れる前から開いていたタブもミュートする |
| ブラウザの起動 | 前回のセッションから復元したタブにも、新しいセッションとして既定（ミュート）を当てる |
| 更新 | Chrome が全タブをアンミュートしてしまい、利用者のアンミュートと区別できない（CON-04） |
| 再有効化 | 同上（CON-04） |

| | |
| --- | --- |
| 優先度 | 必須 |
| 状態 | ✅（再有効化は 1.1.1 から。1.1.0 では再有効化の直後に全タブがアンミュートのまま残り、遷移したタブだけがミュートに戻っていた。2026-10-11 に 1.1.0 のコミット a6bdfd7 を Playwright で読み込んで確認） |
| 仕様 | SPEC-SW-03, SPEC-SW-04 |
| 経緯 | 1.1.1 の開発中に「更新時は利用者のアンミュートを尊重する」を試み、CON-04 のため成立しないと分かった（ADR-0002）。再有効化では Chrome が起動・更新の通知を出さないため、別の検出手段を置いた（ADR-0003） |

## FR-09 ドメインごとにミュートの対象から外せる

| | |
| --- | --- |
| 優先度 | 希望 |
| 状態 | ❌ 未着手。要件の中身は利用者と詰めていない |
| 衝突 | タブのドメインを知るにはタブの URL が要り、`tabs` 権限かサイトへのアクセス権が要る。**NFR-01 と衝突する**。着手する前に、権限を増やすかを利用者に諮ること |
