# 制約条件

要件を満たすうえで前提として受け入れている条件。**変えられないもの**と
**意図的に選んだもの**が混在する。後者は理由を明記する。

---

## CON-01 Manifest V3 で作る

Chrome ウェブストアは Manifest V2 の新規受付を終了している。V3 に従う。

派生する制約:

- バックグラウンドは常駐プロセスではなく Service Worker。**使われていなければ約 30 秒で止まり、次のイベントで起こし直される**
- 止まると JavaScript のグローバル変数は消える。メモリ上に状態を持てない
- `window` / `document` は使えない

| | |
| --- | --- |
| 種別 | 変えられない（プラットフォーム都合） |
| 仕様 | SPEC-MF-01, SPEC-MF-05, SPEC-SW-04 |

---

## CON-02 ビルドステップを持たない

`src/` をそのまま拡張機能として読み込める状態を保つ。配布物は `src/` を zip にしたもの。

**理由:** 個人開発で手を入れる頻度が低い（CON-06）。ビルドツールは数年放置すると動かなくなり、
直すたびに環境構築からやり直しになる。ソースがそのまま動くことを優先する。

| | |
| --- | --- |
| 種別 | 意図的に選んだ |
| 仕様 | SPEC-PKG-01 |

---

## CON-03 拡張機能の中に状態を保存しない

アンミュートしたタブの一覧のような状態を、拡張機能の側に保存しない。
必要な情報は Chrome が持っているもの（タブの `mutedInfo` など）から読む。

**理由:** 保存するには `storage` 権限が要り、NFR-01 に反する。
1.1.0 では保存していたが、読み書きの順序制御・タブを閉じたときの破棄・タブの差し替え（`onReplaced`）での引き継ぎが要り、
Chrome が同じ情報を持っているのに二重に管理していた（ADR-0001）。
メモリ上の変数は CON-01 で消えるので、保存の代わりにならない。

| | |
| --- | --- |
| 種別 | 意図的に選んだ（NFR-01 から派生） |
| 仕様 | SPEC-SW-02, SPEC-SW-04 |

## CON-04 拡張機能を外すとき、Chrome がタブのミュートを解く

Chrome は拡張機能を読み込み直す・止めるとき（更新・無効化）、**その拡張機能がミュートしたタブをすべてアンミュートする。**
そのときのタブの `mutedInfo` は `{ muted: false, reason: 'extension', extensionId: <この拡張機能> }` で、
**利用者がアイコンでアンミュートしたタブと区別できない。**

さらに、無効化から有効に戻したときは、インストール・更新・ブラウザの起動のどの通知も来ない。

| | |
| --- | --- |
| 種別 | 変えられない（プラットフォーム都合） |
| 確認 | 2026-10-11 に Playwright で実測（更新・無効化の両方）。更新は `chrome://extensions` の再読み込みと同じ操作（同じパスでの読み込み直し）で試した。**ストアからの自動更新でも同じになるのは推測** |
| 仕様 | SPEC-SW-03, SPEC-SW-04 |
| 影響 | FR-07 で、更新・再有効化のときに利用者のアンミュートを残せない（ADR-0002） |

---

## CON-05 タブを開いた直後の音声は防げない

Service Worker が止まっているとき、起こし直すのに数百 ms かかる。
その間に新しいタブで再生が始まると、ミュートされるまで音が出る。拡張機能の側では塞げない。

| | |
| --- | --- |
| 種別 | 変えられない（プラットフォーム都合） |
| 影響 | FR-02 |

---

## CON-06 個人開発である

手を入れる頻度が低く、保守に割ける時間が限られる。
仕組みを足す案は、それがあることで増える保守の手間と比べて決める。
